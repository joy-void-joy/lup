# The runtimes

The runtimes lup holds sessions on, Claude Code and Codex, behind one interface, so nothing outside `lup.runtimes` names one (`AGENTS.md`, *lup's code*).

A runtime (`Runtime`, `runtime.py`) is five interfaces its own classes fill (`claude.py`, `codex.py`), and `Core.runtimes` holds each as an entry, which a project drops or replaces as it would any (`known.py` lists lup's own):
- **`Rooming`:** what a session's room needs to run it: the files lup writes for it (its settings, its tool server's entry, its guidance at system level), the variables it runs with, and its command, held by lup over its input and output or in a terminal; the file its sign-in writes, which an account's login is mounted as; and what of its own directory is the history every room of a project shares.
- **`Hooks`:** the hooks lup listens at, each read as one of lup's events (`lup.sessions.events`), and lup's answer spelled as the runtime reads one: words told beside it, a call refused, or lup's stamp on a subagent's call to lup's own tools naming their conversation.
- **`Holder`:** how a session is held over its runtime's input and output (`Holding`): Claude Code's stream-json, named up front with `--session-id`; Codex's `app-server`, a thread opened by the holder and named by Codex.
- **`Channel`:** where the newest CLI is fetched from, each checked against its vendor's checksum, the fetching its caller's (`Got`), so no code here reaches the network.
- **`Records`:** how its records of each conversation are read (below).

No SDK holds either runtime: both SDKs start the CLI on a pipe, which another process of the operator's can reopen through `/proc` and type into, so lup speaks both protocols itself, reading only what it needs and leaving what it doesn't know (`docs/field-notes.md`, *A session held with no terminal*). What each runtime's settings rest on is in its module's docstring.

## Records

Each runtime writes a record of every conversation it holds, a line of JSON at a time, and only ever adds to it: Claude Code a `.jsonl` for a session and one for each subagent, Codex a rollout for each thread. `Records` (`records.py`) is the interface every runtime fills to read them, so the dashboard's conversation buffer and transcripts read every conversation in one shape:
- **`found(home, under=…)`** lists the records in one of the runtime's homes, its own directory or a copy kept in its layout: each a `Record`, its path, the runtime's ids for the session and, for a subagent, their conversation, who spawned them and with which call, and the directory it ran in. A file that isn't one of the runtime's records is left out.
- **`read(record, since)`** reads the steps a record added since the read that stopped at `since`, and says where this read stopped (`Reading`): a byte offset, a digest of the first line, and what the runtime's reader carries from one read to the next, as JSON its caller keeps. So a record is never read whole again as it grows. Only whole lines are read, and a line still being written waits for the next read. A line past `longest` is skipped without being held, since a record is the room's to write. A record that shrank, or whose first line changed, is read again from its start, and `again` says so.

**Steps**, in the order the record has them, each with its place (the byte its line starts at, and its index among that line's steps, which never moves as the record grows), when it was written, and the runtime's own id for it where there is one (Claude Code's `uuid`, the same on a fork's copy of a parent's line as on the parent's):
- `Said`: words, and who said them: the operator in the runtime's terminal, the agent, lup writing into the session (a turn it held, a hook's context), another conversation (a subagent's brief, a peer's message), or the runtime itself. Words sent while the agent works are `queued`.
- `Called` and `Returned`: a call by the runtime's id for it, the one its hooks and lup's events carry, the tool named as the hooks name it (`mcp__lup__ask` on both runtimes), and what it returned, whole. A call made inside another, as Codex's code mode calls tools from an `exec` cell, says which (`within`). `Refused` is a call a hook refused before it ran.
- `Ended`, a turn's end; `Compacted`; `Titled`, a name, the operator's or lup's winning over the runtime's; `Forked` and `Continued`, a conversation going on from another's history or in another record.
- `Counted`, the context the latest request took; `Planned`, the agent's task list as it stands.

Each reader also says where the operator's own directory for its runtime is (`own`: `~/.claude`, `~/.codex`), where the sessions they run outside lup keep their records, and which files reading a record reads beside it (`beside`: a subagent's spawn, an output saved whole). `copied(records, home, into)` copies a home's records into `into` in the same layout, appending what a record added since and copying any other file whose copy differs, never through a link, so a copy is read as the home is and the runtime's cleanup of the home leaves it whole.

What each runtime's lines are read as, and what that rests on, is in its reader's docstring (`claude_records.py`, `codex_records.py`), against `docs/field-notes.md`. A room writes its records, so a link planted among them could point at any file of the operator's: every file a reader opens, a record, a spawn's or a saved output, is read only where its resolved path lies inside the home it was found in (`Record.home`, `confined`), and nothing is opened through a link at its last step or waited on as a pipe. Where each stretch of a session ran, and when it was resumed, isn't the record's to say: lup knows, since it starts every session.
